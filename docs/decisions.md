# Architectural Decision Records (ADRs)

## ADR 001: Separation of Authorship and Deception
- **Status:** Accepted
- **Context:** Online reviews can be written by humans or generated by LLMs. In both categories, a review can be truthful (genuine customer experience) or fraudulent (paid spam, competitor sabotage, fake engagement).
- **Decision:** Never collapse authorship and deception into a single binary "fake review" classification. Maintain two independent classifiers and combine them into a 2x2 matrix yielding four verdicts:
  1. `genuine_human` (Human + Genuine)
  2. `deceptive_human` (Human + Deceptive)
  3. `ai_genuine` (AI + Genuine)
  4. `ai_deceptive` (AI + Deceptive)
- **Consequences:** Provides actionable transparency to platform trust & safety teams and end consumers.

## ADR 002: Deterministic Stub Mode with Fallback Safety
- **Status:** Accepted
- **Context:** Training takes place remotely in Google Colab (GPU). The web application and backend must be fully runnable locally and in staging environments even before weights are placed in `api/models/`.
- **Decision:** The API checks for the existence of trained artifacts on startup. If missing, it gracefully enters `stub` mode, generating deterministic probabilities and token weights based on cryptographic hashes of the input text and simple heuristics. A prominent UI banner alerts the user to demo mode.
- **Consequences:** Zero runtime crashes from missing weight files, continuous testability of UI and API pipelines.

## ADR 003: Token Attribution Directionality
- **Status:** Accepted
- **Context:** The explanation component displays token-level contributions to both classification decisions.
- **Decision:** Adopt a consistent polarity convention across both tasks:
  - **Positive weight (> 0):** Pushes the classification towards the suspicious / target class (`ai` for authorship, `deceptive` for deception). Rendered in red/warm colors.
  - **Negative weight (< 0):** Pushes the classification towards the baseline class (`human` for authorship, `genuine` for deception). Rendered in green/cool colors.
- **Consequences:** Consistent, unambiguous user mental model across both views.

## ADR 004: Unified Data Schema with Orthogonal Label Isolation
- **Status:** Accepted
- **Context:** Available academic datasets specialize in different aspects (e.g., Ott et al. focuses on deception; RAID benchmark focuses on AI vs. Human authorship).
- **Decision:** Define a unified schema: `text`, `source_dataset`, `authorship_label` (`human` | `ai` | `unknown`), `deception_label` (`genuine` | `deceptive` | `unknown`), `domain`. Each task's training pipeline filters solely on rows where its respective label is known.
- **Consequences:** Prevents label corruption or artificial imputation while maximizing training set size per task.
